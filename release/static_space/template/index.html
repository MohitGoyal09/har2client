A benchmark and RL environment for API clients

Beam writes a near-perfect API client from recorded traffic, until the recording leaves one header out.

It scores {{H1_VISIBLE}}% when the recording shows everything and {{H1_HIDDEN}}% when one header is hidden. Give it the missing piece and it recovers to {{H1_SUPPLIED_LOW}} to {{H1_SUPPLIED_HIGH}}%.

01 The task

A recording in, a client out, hidden tests on a server the model never saw.

  1. Recording GET /v2/invoices?page=2
    200 application/json

    A HAR file: the requests and responses of one real or invented API, plus a goal that names the methods to write.

  2. Model Beam, GPT-OSS,
    Qwen

    Reads the files and writes one Python file. No LLM judge anywhere in the loop.

  3. client.py class Client:
      def list_invoices(...)

    Must work for any host, key and data, so replaying the recording does not pass.

  4. Hidden tests fresh server
    new data, keys, host

    The score is the share of hidden tests that pass.

07 Method

Hidden tests, no judge, hypotheses written first.

Grading

Each task starts a new fake server with new data, a new key and a new host. The submitted client.py runs against it. A hidden test suite counts what passes. A client that copies the recording fails. Missing submissions count as failures. API errors are excluded and stay visible in the raw files.

How Beam was used

  • Model Beam-1.0-501B-A23B through Reflection's OpenAI-compatible API, with reasoning_effort set to low, medium or high on every call.
  • Cases 1 and 3 are one call with no tools. Case 2 is multi-turn tool calling: http_request to the practice server and submit_client to end. The reasoning_content of each assistant turn is sent back in the next request.
  • Beam at high effort in cases 1 and 3 is the mean of 3 runs per task. Everything else is one run.

Comparing models

  • GPT-OSS-120B and Qwen3.5-397B-A17B ran through the Hugging Face router (provider Novita), one run per cell.
  • Their output was capped at 32,768 tokens per call. Beam's runs used 65,536.
  • Qwen was run with thinking on. It has no effort levels, so it is never labelled low, medium or high and is not equivalent to any Beam effort.
  • Intervals are percentile bootstraps over tasks ( resamples).
